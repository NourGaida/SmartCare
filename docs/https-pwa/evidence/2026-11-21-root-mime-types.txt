# Evidence — root MIME type incident (2026-11-21)

## Root cause hypothesis (CONFIRMED before fix)

`docker/nginx-mime-types.conf` was included inside `location ^~ /frontoffice/` and `location ^~ /backoffice/`. Its complete content at the time was:

```text
types {
    text/css css;
    application/javascript js;
    text/javascript mjs;
    application/manifest+json webmanifest;
    image/svg+xml svg;
    image/png png;
    font/woff2 woff2;
}
```

In nginx, `types` is not additive: a `types` block in a more specific context replaces the whole inherited table. `location /` uses `try_files /frontoffice$uri /frontoffice$uri/ /frontoffice/index.html`; for `/`, the directory match internally redirects to `/frontoffice/index.html` on the patient host and `/backoffice/index.html` on the staff host. Those requests land in the prefix locations whose partial table has no `text/html`, so nginx falls back to `default_type application/octet-stream`.

`http://app.smartcare.local/` returned `301` to HTTPS (VERIFIED earlier and unchanged here).

`X-Content-Type-Options: nosniff` was present. That is correct behaviour: once the server advertised `application/octet-stream`, Chrome would not guess HTML and downloaded the response instead.

## Why the earlier 39-pass smoke run missed it

The earlier script built its URL list from `href`/`src` attributes in `index.html` plus explicit assets (`sw.js`, icons, fonts, `server-mode.mjs`). An HTML document never references itself as `/`, and the script did not explicitly request `/`, `/frontoffice/index.html` or `/backoffice/index.html`. Therefore it only exercised locations that returned the handful of MIME types present in the partial table, and the broken internal-redirect path was never tested. The new script adds those four HTML paths for both hosts and explicit css/mjs/svg/png/woff2/json/webmanifest assertions.

## Fix (VERIFIED)

- Chosen option: complete global MIME table, no location overrides (ADR-0010).
- `docker/nginx-mime-types.conf` is now the full `nginx:stable` MIME table plus `text/javascript mjs;` and `application/manifest+json webmanifest;`.
- It is mounted at `/etc/nginx/mime.types`, which nginx already includes at `http` scope.
- All `types { }`, `default_type` and snippet includes were removed from `docker/nginx-https.conf`.
- `X-Content-Type-Options: nosniff` remains enabled.
